# Report C — Camera control the model obeys; long-horizon evaluation (subagent, 2026-10-08)
V = read in paper/code by the agent's readers; I = inferred. Corrected IDs: AC3D = 2411.18673, ReCamMaster = 2503.11647.

## Part 1 — camera control
- CameraCtrl (2404.02101): Plücker -> adapter pyramid, merged by zero-init linear inside the first temporal self-attn of every motion module; temporal-attn injection > spatial; RE10K 65K clips, 50K steps, 16-32 A100. Metric: summed RotErr/TransErr via COLMAP on generated frames; GT floor TransErr 6.93 / RotErr 1.02.
- CameraCtrl II (2503.10592): Plücker through a second patchify layer added ONCE before all DiT blocks; injecting in every layer cuts motion strength (307 -> 247) with no camera gain. VGGSfM ATE-style metric, mean not sum.
- CamCo (2406.02509): Plücker concat + epipolar cross-attn to first-frame features; Plücker-only ~ epipolar-only on Trans/Rot; removing Plücker multiplies SfM failure.
- AC3D (2411.18673): camera side blocks only in the first 8 of 32 blocks; linear probing: camera knowledge peaks at layers 13-21; camera motion is low-frequency and fixed in the first ~10% of denoising -> training noise truncated to t in [0.6,1], conditioning only on the first 40% of the reverse trajectory; conditioning all blocks worsens FVD ~10% with no gain.
- ReCamMaster (2503.11647, Wan2.1-1.3B): source latents concatenated on the FRAME axis (beats channel concat); 12-d extrinsics -> FC added in every block before self-attn; UE5 136K videos, 10K steps.
- CamCloneMaster (2506.03140): no camera parameters; reference motion video tokens frame-concatenated; frame-concat >> channel-concat >> additive ControlNet branch ("feature addition makes it harder to distinguish motion cues").
- Uni3C (2504.14899, Wan2.1-I2V-14B frozen + 0.95B side DiT): side input = noisy latent + VAE latent of the rendered point-cloud video; Plücker only in the side branch; 6K steps, 64 H100 x 40 h. Decisive ablation: Plücker-only ATE 0.402 / Pcd-only 0.091 / Plücker+Pcd 0.102 -> adding Plücker to the render slightly HURTS on normal trajectories; helps only on 360-degree turns where the render is empty (1.33 -> 1.01). Point clouds converge after ~1K iters.
- SEVA (2503.14489): no render; Plücker twice (input concat + FiLM in every ResBlock); 1.3B full training 700K iters; ATE 0.077 in Uni3C's table (strongest embedding-only controller, full-model training).
- GEN3C: render-only; a vestigial plucker key is never consumed. ViewCrafter Table III: Plücker variant R/T 2.69/2.57 vs point-cloud 0.55/0.98 at identical injection (~5x worse).
- Wan2.2-Fun-5B-Control-Camera (fine-tuned from Wan2.2-TI2V-5B): Plücker video bypasses the VAE, 4 frames stacked -> 24 ch per latent frame -> SimpleAdapter (not zero-init) added to patch embeddings once before all blocks. Closest to our Plücker route on our base.
- AlayaWorld v1.1: "The dedicated camera AdaLN branch is removed ... the planned camera trajectory is used to determine the viewpoint from which the 3D point cache is re-rendered"; no ablation.
- Others on Wan: CETCam (Plücker-token variant worse than reprojection + explicit tokens), MeRoPE (Wan2.2-5B, camera as metric RoPE), UCPE, DepthDirector (Wan2.2-5B LoRA, warped depth+mask), Generated Reality, Track2View, InfCam, WorldStereo; CamVerse GRPO with pose-error reward (-15-26% camera error).
- Metric conventions: CamI2V CamMC; RotErr/TransErr summed and canonicalised; estimators COLMAP/ParticleSfM/VGGSfM/GLOMAP/MegaSaM/VGGT/ViPE/DROID-SLAM/DUSt3R/pi3; not cross-paper comparable. No standard "camera adherence" benchmark; WorldScore/WBench/WorldRoamBench nATE are de facto.
- Does the render dominate the embedding when both are present? Yes in every measured case (Uni3C, ViewCrafter, CETCam, AlayaWorld, CamCloneMaster). Two explanations for our g=0.00: the render already carries translation so a zero-init branch never gets gradient; and camera is decided in the first ~8 blocks and first ~10% of denoising, so an additive route trained at uniform t on late blocks is off-target.
- Agent's conclusions: (1) treat the scaffold render as the camera channel; report camera error with VGGT/ViPE nATE; (2) if an embedding route must exist for empty-render cases, inject once at patch-embed / first <= 8 blocks, train with t in [0.6,1], with camera- and render-dropout; (3) measure command-response per call from pi3/VGGT vs commanded after Sim(3), with a render-dropped arm as control; CamVerse GRPO is the only verified direct adherence fix.

## Part 2 — evaluation
- WorldScore (2504.00983): DROID-SLAM camera error e_cam = sqrt(e_theta * e_t) normalised; 3D consistency = DBA reprojection; photometric = SEA-RAFT fwd-bwd; style = Gram first vs last; subjective = CLIP-IQA+ and LAION aesthetic; motion = median flow; smoothness = VFIMamba.
- WBench (2605.25874) / WorldPlay2: multi-turn; MegaSaM nATE_t/nATE_r (navigation falls ~33 points from turn 1 to 4+); roundtrip DreamSim; TransNetV2 hard-cut fraction; DA3 reprojection; SAM2-masked DINOv2; LAION, MUSIQ, flicker, RAFT dynamic degree, AMT smoothness, HPSv3. RevisitBench: 200 palindromic trajectories, PSNR/SSIM/LPIPS/MEt3R between mirrored pairs.
- VBench/VBench-Long: subject = DINO cosine, background = CLIP, flicker = global consecutive MAE (a single seam is diluted), smoothness = AMT, dynamic degree = RAFT, aesthetic = LAION, imaging = MUSIQ. Self-Forcing++: VBench "tends to overrate degraded and over-exposed frames".
- Drift metrics: Rolling Forcing dDrift = |MUSIQ(first 5 s) - MUSIQ(last 5 s)|; Self-Forcing++ Visual Stability (Gemini rubric); BlockVid VDE; WorldRoamBench D = (worst - best)/|best| over 10 segments, TrajScore = 1 - (nATE_t + nATE_r)/2 with ViPE; Pathwise TTC JEPA-Diff (frozen V-JEPA/DINOv2 drift from frame 1); Steady-Forcing separates drift from stagnation; SNF-Bench static-region ORB displacement and flow.
- Seam/flicker priors near-identical to our seam ratio: Forcing-KV (2605.09681) Chunk Discontinuity = top-(K-1) RAFT flow differences / mean; HeadCast (2607.20125) Block-Boundary Discontinuity = boundary pixel-MAE / within-block MAE; Pathwise TTC t-LPIPS at boundary pairs; WorldMark mutation. Mainstream AR papers report no boundary metric.
- Over-saturation / naturalness: APG (2410.02416) Saturation = mean HSV-S, Contrast = grayscale std, + FID/ImageReward; LF-CFG saturation + KID; no-reference tools CLIP-IQA+, MUSIQ, LAION aesthetic, Q-Align/OneAlign (video), DOVER; Pathwise TTC colour-shift hue-histogram first vs last. "Invented detail" has no standard metric beyond VLM judges and reference DINO.
- Revisit: WorldMem PSNR/LPIPS/rFID vs previously generated frame at the same pose; CaM rotate-and-return; LTSM reversed trajectories; WorldPlay cycle vs first pass MEt3R; R2M-Bench (2608.27328): absolute revisit similarity rewards static rollouts -> MemoryGain = s_rev - s_base with gap-matched non-revisit control pairs, NMR normalised (DreamX-World-Memo 0.706 > HY-WorldPlay 0.485 > Matrix-Game 3.0 0.403 > Lyra-2 0.310 > SANA-WM 0.016); WorldCycle/CycleBench; LoopNav (SSIM/LPIPS too alignment-sensitive).
- Pose adherence: all benchmarks align the whole trajectory once (Sim(3)) then report geodesic rotation and scaled translation error; nobody aligns per chunk.
- Our metrics vs accepted counterparts: late DINO-to-recording -> accepted analogues exist (VBench-Long fast branch, JEPA-Diff), reference-to-recording unusual but defensible; KID fine as supplement; Laplacian sharpness ratio -> no counterpart, keep as diagnostic; motion ratio -> partial (dynamic degree, static-region flow), restrict to static regions; seam ratio -> cite Forcing-KV / HeadCast, add t-LPIPS. Missing and expected: camera error (named estimator, Sim(3), nATE), revisit with gap-matched control (R2M NMR) or palindromic PSNR/LPIPS/MEt3R, VBench subset, saturation (HSV-S) + Q-Align/DOVER, user study or VLM Visual-Stability judge.
- Agent's conclusions: (1) reviewer-default stack = VBench subset + MUSIQ/LAION per window with first-vs-last dDrift + FVD; keep DINO and seam ratio relabelled with citations, add t-LPIPS; (2) add ViPE/VGGT nATE per turn and R2M-style revisit with controls; (3) for over-guidance report HSV-S saturation and contrast deltas, Q-Align/DOVER, KID, VLM Visual-Stability; state that VBench/LPIPS overrate blurred and over-exposed frames.
